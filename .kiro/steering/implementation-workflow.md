# 実装ワークフロールール

## 設計書ファースト

タスクの実装を開始する前に、必ず設計書をユーザーに提示し、承認を得てから実装を行う。
承認なしに実装を進めてはならない。

### 設計書に含める内容

1. **概要** — 何を作るか・なぜ作るか
2. **作成・変更するファイル一覧** — ファイルパスと内容の説明
3. **インターフェース・API定義** — 公開する型・関数・クラスのシグネチャ
4. **用語の説明** — 設計書内で使う専門用語・略語・固有名詞をわかりやすく解説する
5. **動作の説明** — 主要なケースの挙動（箇条書き・表・図）
6. **テストの方針** — 何をどう検証するか

### 用語説明のルール

- 設計書内で初めて登場する専門用語・略語・固有名詞には必ず説明を加える
- 例: `Renderer`（描画命令を受け取るインターフェース）、`PadEngine`（DOMに依存しない描画ロジック層）

## 実装後の確認

実装後は必ず以下を順番に実行し、全てパスしてからコミットする。

```
# 1. テスト
node_modules\.bin\vitest.cmd run --project web

# 2. 型チェック
node_modules\.bin\tsc.cmd -b

# 3. ESLint
node_modules\.bin\eslint.cmd apps/web/src

# 4. Prettier（CIと同じ検査）
node_modules\.bin\prettier.cmd --check .
```

Prettierでエラーが出た場合は `--write` で修正してから再確認する。
